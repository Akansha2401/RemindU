## Commands

Bun is the package manager (`bun.lock`). Never use npm/yarn — mixed lockfiles cause drift.

```bash
bun install                          # install deps
bun expo start                       # dev server (Expo Go)
bun expo start --dev-client          # dev server for the installed development build
bunx expo install <pkg>              # add a package (SDK-compatible version); prefer over `bun add`
bunx expo lint                       # lint
bunx tsc --noEmit                    # typecheck
bun run test                         # unit tests (jest-expo); one file: bun run test -- src/features/onboarding/__tests__/store.test.ts
bunx expo prebuild --platform android --clean   # regenerate android/ after app.json/plugin/native-dep changes
```

Typed routes (`.expo/types/router.d.ts`) are regenerated by the dev server. If it can't run (e.g. file-watcher limits), regenerate with `EXPO_ROUTER_APP_ROOT=$PWD/src/app node -e 'require("@expo/router-server/build/typed-routes").regenerateDeclarations(".expo/types")'`.

Local Android dev build (APK for a physical device, see `Eas.md`): `bunx expo prebuild --platform android`, then `cd android && ./gradlew assembleDebug -PreactNativeArchitectures=arm64-v8a` (arm64 only — won't run on x86 emulators). `android/` and `ios/` are git-ignored generated output.

## Architecture

Expo SDK 57 / React Native 0.86 / React 19, with `typedRoutes` and the React Compiler enabled in `app.json`. Path alias `@/*` → `src/*`.

- **Routing / auth gate** (`src/app/_layout.tsx`): `Stack.Protected` guards driven by `authStore$.isLoggedIn`. Logged out → the `(onboarding)` group (welcome → persona → goal → why → apps → permissions → sign-in/email/verify). Logged in → `(tabs)` (Home, Sessions, Goals, Profile, with a custom `TabBar` whose centre + opens the `add` sheet, a transparent modal), `session/[id]`, `goals/new`, `settings/*`, `trial`, `attribution`, `limits/*`. `gate` and `auth/callback` sit outside the guards. `authStore$` follows the Supabase session (`onAuthStateChange`) and is persisted so the first render picks the right stack.
- **Onboarding** (`src/features/onboarding/`): pure rules in `logic.ts` (unit-tested), answers in the persisted `onboarding$` store. Every screen calls `useOnboardingStep(step)`, which records the step (resume after Android Settings/restart) and fires the `onboarding_step` event. After sign-in, `features/auth/actions.ts` copies answers into `setup$`, pushes them to `profiles`/`goals`/`app_rules` (retried via `syncPending`) and gives each picked app a waiting timer.
- **Native guard** (`src/lib/guard`): apps, permissions, per-app timers and screen time from the `app-limiter` module (a mock in Expo Go/iOS). Each app gets one timer (`AppSession`): it waits until the app is first opened, counts down only while that app is in the foreground, logs every visit, and at zero the foreground service opens `remindu://session/<id>`. The service is the source of truth; `sessions$` mirrors it via 1s polling (`useSessionPolling`) on visible screens.
- **Stats** (`src/features/stats`): pure, unit-tested rules (streak, heatmap, chart bars, overview) over active timers plus `history$` (persisted: ended timers with their logs, and daily screen time, saved as read because Android keeps only about a week of usage events).
- **Copy and config**: all user-facing strings in `src/constants/strings.ts`; persona suggestions, suggested apps and phone-brand guides in `src/config/onboarding.ts`; feature flags (trial screen off) in `src/config/flags.ts`; privacy/support links in `src/config/app.ts`.
- **Goals and profile**: TanStack Query hooks in `features/goals/api.ts` and `features/profile/api.ts` (one active "focus" goal, optional N-day challenge; sign-out and account deletion via the `delete_my_account` RPC clear local data too). The theme preference (system/light/dark) lives in the persisted `prefs$` store and is applied in the root layout.
- **Client state**: Legend State v3 beta. Read observables in render with `useValue` (not `use$`/`.get()` — React Compiler is on), and push subscriptions down into small leaf components for fine-grained updates. Shared types live in `src/types/`.
- **Server state**: TanStack Query. The single `QueryClient` lives in the root layout. React Native has no window focus/online events, so the root layout wires them up manually: `useAppState` → `focusManager`, `useOnlineManager` (NetInfo) → `onlineManager`. Per-screen helpers: `useRefreshOnFocus` (refetch when a screen regains focus, skipping the first mount) and `useRefreshByUser` (pull-to-refresh state).
- **Backend**: Supabase client in `src/lib/supabase.ts` (typed with `src/types/database.ts`, PKCE flow for Google OAuth). Migrations in `supabase/migrations/` (file versions match the remote project). Sessions persist via `expo-sqlite`'s `localStorage` polyfill (`expo-sqlite/localStorage/install`). Config comes from `EXPO_PUBLIC_SUPABASE_URL` and `EXPO_PUBLIC_SUPABASE_PUBLISHABLE_KEY` in `.env` (`EXPO_PUBLIC_*` vars are inlined into the client bundle — never put secret keys there).
- **Styling**: NativeWind v4 (Tailwind 3) via `className`. Entry CSS is `src/global.css` (imported in the root layout, configured in `metro.config.js`). The design system follows react-native-reusables / shadcn conventions (`components.json`): CSS variables in `global.css` + `tailwind.config.js`, the mirrored JS palette and `NAV_THEME` in `src/lib/theme.ts` (keep them in sync), `cn()` in `src/lib/utils.ts`, UI components intended for `@/components/ui`, and `<PortalHost />` mounted in the root layout for portal-based primitives. Tokens follow the RemindU Design System v1 (cream/terracotta/espresso); dark mode is derived from the check-in "takeover" palette and read with NativeWind's `useColorScheme`. Font is Plus Jakarta Sans: always render text with `Text` from `@/components/ui/text`, which maps `font-*` weight classes to the right font file (Android can't synthesise weights). Type scale: `text-display/quote/title/section/button/body/label/caption`; colours `cocoa` and `walnut` are the label/body browns (named to avoid clashing with those font sizes).

## Git workflow (from README)

- Never commit to `main`. Never work directly on `development` — create a short, lowercase, hyphenated feature branch from the latest `development`, merge `development` back into it and test before merging the feature into `development`.
- Conventional Commits: `<type>(<scope>): <subject>` — imperative, lowercase, no trailing period, ≤50 chars. `style` means code formatting only; visual/UI changes are `feat` or `fix`.
